# First installation: guided walkthrough

Run the installer from the checkout with no arguments:

```bash
bash install.sh
```

From Windows PowerShell, use Git Bash through one line:

```powershell
& "C:\Program Files\Git\bin\bash.exe" .\install.sh
```

You do not need to know a service URL, port, project name or token-file path to start. The wizard offers local setup on this computer first, then hosted setup. Enter `q` at a question to pause. Run the same command again to continue saved progress or start a separate fresh setup.

## Choose where the ledger lives

**On this computer:** Conductor keeps task metadata in a private SQLite database in your local state directory. Codex starts the MCP bridge when needed; no separate VM, Docker container, listening port, SSH login, or service key is needed. This is the simplest path for one person. Separate isolated desktop and VS Code profiles can share the same local ledger. The guided route creates the data under `%LOCALAPPDATA%\Conductor` on Windows or the XDG state directory on Linux. An advanced install can select a different directory on a local disk.

**On a Linux host:** A shared service stays running so several people can connect from their computers. Each user needs their own account and private service key issued by the host administrator. Choose this when you need shared availability or access from multiple machines.

## Hosted service and client

The **service** is a small Linux application that records task plans, worker IDs and results. The guided hosted route runs it in Docker and stores its database on local persistent volumes. It does not run the AI agents, need your Codex sign-in or require copies of your projects.

The **client** is the local connection and skill used by Codex. Your Codex desktop app or VS Code extension runs the actual native workers. You sign in to Codex separately. A working service connection does not add native worker tools to a client that does not have them.

A **Conductor connection file** contains the key generated by the service. It is different from any GitLab/GitHub token used to download private source. The new-install route creates and transfers this file privately. It never asks you to invent a key, paste its value, or use a Git-host token to connect Conductor.

## Before starting

The Codex computer needs Python 3.11+ and Bash; on Windows use Git Bash with native Windows Python and the Windows OpenSSH Client optional feature. Git Bash is the entry shell; the installer selects native Windows OpenSSH explicitly, rather than Git's bundled SSH. If Windows OpenSSH is missing, enable the OpenSSH Client optional feature and rerun setup. Install the desktop app and/or VS Code if you want to open those clients. The wizard detects client prerequisites and offers to pause or prepare connection profiles for later use.

The hosted route needs a Linux computer or VM with Python 3.11+, Docker Engine, a running local Docker daemon and Docker Compose. For another machine, you need an SSH login that you control and permission to use Docker there. SSH may ask for the Linux password or private-key passphrase; that is your Linux login, not a Conductor or Git-host token. The wizard uses a separate SSH known-hosts file for its test session. The on-device route has none of these host prerequisites.

If you have no suitable Linux host yet, choose that answer. The wizard provides a prerequisite checklist and stops before asking for a connection file or configuring Codex. It does not provision a VM or silently install operating-system packages on an existing machine.

## New installation

Choose **New installation - guide me through the service and clients**, then **On this computer** for local mode or a Linux host for hosted mode.

1. Choose this Linux computer or another Linux VM/server over SSH. On Windows the service route uses another Linux host. Enter the server IP address (or host name), your Linux SSH username and port (usually 22). The wizard tries your SSH configuration, agent and saved private keys automatically. If no saved key works, SSH can ask for your Linux password. A private key is used in place; it is not copied to the service.
2. The wizard checks Linux, Python, Docker and Compose before installing. Missing prerequisites are explained with a next action. No token is requested at this stage.
3. The wizard prepares an owned source copy and a separately named Docker Compose project. It selects a free private connection number, builds and initializes the service, and waits for health. Existing user deployments are not selected.
4. The service generates its key. The wizard exports and transfers it into a private local file without displaying it. For a remote service it establishes SSH forwarding and verifies authenticated service health. Key/agent authentication can run in the background; Windows password authentication uses a dedicated SSH login window. Keep a visible SSH login window open while using the test clients.
5. Choose desktop, VS Code or both. The wizard prepares isolated Codex homes and project-local skills, then starts each local MCP bridge briefly to verify initialization, all 14 tools and authenticated coordination health. It reports a failed connection as incomplete; it does not claim client readiness from copied files alone.
6. Open the isolated VS Code client now or finish and open it later. Sign in there; VS Code opens its test workspace. For Codex desktop, use a separate Windows account/VM or explicitly configure your usual Codex profile, restart the app, and start a new chat. Run the single [quick setup check](acceptance.md#quick-setup-check) in each real client.

If a later prerequisite or connection check fails, the created service and private progress are preserved. Continue the same setup to retry the connection/profile stage; a saved service is checked rather than rebuilt or replaced. Deliberate service upgrades are a separate operation.

## Connect to an existing service

Choose this route only when Conductor is already running. The wizard first asks whether you actually have both the service and its private connection file. Answering no returns to service-first guidance.

For SSH, supply the Linux SSH login, SSH port and the service's connection number. For an existing HTTPS endpoint or an already-running tunnel, supply its `/mcp` URL. Then select the private **file path** supplied by the service owner. Do not paste a key value into that question. A missing file or rejected key stops before client profiles are configured.

If the owner has not exported a connection file, they can use the same installer on the Linux host:

```bash
bash install.sh server --export-token "$HOME/.local/share/conductor-private/service-token"
```

They must use the service's actual `--project` name when it differs from the default. The entry point creates a missing private parent, refuses overwrites/insecure permissions and does not print the credential. Transfer that file securely to the Codex computer. The new-install route handles this for you.

## What is isolated

Private setup progress, connection files, profiles and working directories live under the checkout's `.codex/guided-install/`. The shared Python environment is under `.codex/conductor-venv`. Each profile has a separate Codex home, file-based Codex authentication and a workspace-local skill. Normal Codex configuration and global skills are not selected by the guided path.

VS Code launch uses separate editor data and extension directories as well as its test Codex home. Its extension is installed only into that test editor. Automatic isolated Codex desktop launch is not supported by this installer: the Windows app routes a second launch back to the running instance. Use a separate Windows test account/VM for an isolated desktop check, or explicitly install into your usual Codex profile, restart Codex, and start a new chat.

To reopen a prepared profile from the same checkout:

```bash
bash install.sh launch --profile desktop
```

```bash
bash install.sh launch --profile vscode
```

These commands recheck the saved connection and reestablish its owned SSH tunnel if necessary before opening the test client. They do not reinstall the prepared runtime or close existing app windows. Keep the checkout at its installed path; moving it breaks recorded executable paths. For removal and service/data handling, see [operations](operations.md) and the advanced [client reference](client-setup.md).

## What counts as success

Service health, a private connection file and a passing MCP handshake mean the service connection is ready. They do not establish native delegation in desktop or VS Code. Run the short setup check in the actual client and record its version and exact native worker IDs.

## Earlier candidate setups

An owned, undeployed setup from the earlier Firstmate candidate can resume with the same saved SSH answers and checkout path. The installer saves its original state privately before assigning the new Conductor service name. Existing folder names do not need to change.

A candidate that already deployed a service is preserved, including its database, Docker project, connection files and profiles. The wizard offers a separate fresh Conductor setup. It does not upgrade an active older service or replace a normal installed client automatically.
