# Five-worker handoff benchmark

On October 28, 2026, updated worker handoffs used **23.91% fewer total recorded
tokens** with a **10.093-second runtime increase**, accepted by the project owner
as a useful tradeoff. Both runs passed the same acceptance suite.

| Metric | Original policy | Updated handoffs |
| --- | ---: | ---: |
| Workers / observed peak active workers | 5 / 2 | 5 / 2 |
| Total input plus output tokens | 1,639,744 | 1,247,639 |
| Input tokens | 1,630,820 | 1,237,678 |
| Cached input tokens (included in input) | 1,592,576 | 1,175,552 |
| Uncached input tokens | 38,244 | 62,126 |
| Output tokens | 8,924 | 9,961 |
| Reasoning tokens (included in output) | 1,086 | 1,187 |
| Model requests: manager / workers | 26 / 20 | 23 / 20 |
| Total worker tokens | 750,897 | 410,558 |
| Elapsed seconds | 210.768 | 220.861 |

## Controls and changes

Both runs used GPT-6 Sol (`gpt-6-sol`), medium reasoning, Codex CLI
`0.165.0-alpha.1.2`, the same initial source stubs, 16,000 characters of identical
archived background, the same five worker roles and three-phase ordering, and
the same runtime concurrency setting (`agents.max_threads=4`, depth one).
Each run demonstrated a peak of two active workers. Fresh fixtures ran
sequentially. Recorded contexts confirmed model and effort for all twelve agents.

Two workers implemented an ASCII slug function and duration parser, followed by
two independent reviewers, then a separate integrator. The unchanged acceptance
suite contained five test methods covering 30 inputs. Both policies received
the same predefined check runner and complete role packets. Every role produced
a successful test/scope receipt. The test-local transport used the real
Conductor dispatcher and completion gates without changing live service state.

The updated policy forwards complete operational packets and uses fresh context
when those packets are sufficient. Workers receive relevant rules, ownership,
environment facts, exact commands and completion evidence requirements together.
In the updated run there were no worker availability probes, Git calls, ad hoc
Python tests, cleanup calls or generated bytecode files. Worker model requests
stayed at 20 while their total tokens fell 45.3%.

## Accounting and limits

Totals include the manager and every recorded descendant. Per-response usage is
attributed to its actual thread and deduplicated; inherited parent records are
excluded from child accounting. Cached input is a subset of input, reasoning is
a subset of output, and neither is added twice. Development, setup and reporting
usage is excluded from the measured task totals.

This is one exploratory pair with uncontrolled cache state and model sampling,
not a statistical guarantee, a near-full-context stress test, or macOS/desktop/
VS Code/live-SSH acceptance. The original strict no-runtime-increase criterion
was not met; the owner accepted the ten-second tradeoff afterward. Uncached
input rose 62.45% and output rose 11.62%. Total-token savings are not equivalent
to an established invoice or account-allowance saving.

An earlier five-versus-three-worker comparison was confounded by team size and
was withdrawn. A subsequent equal-team trial without these operational fixes
was worse. The results above are the fresh equal-team run after correcting the
handoffs and supplying identical predefined check tools to both arms.

## Reproduce

The frozen measured policies and portable numeric summary are in
[`benchmarks/token-efficiency/`](../benchmarks/token-efficiency/). The published
skill also preserves newer macOS/MCP transport guidance; the frozen candidate
records the exact policy used in the measured pair. Runtime-specific paths,
account identifiers and raw transcripts are intentionally not published.

From a checkout with Python and a signed-in Codex CLI, choose the same supported
model/effort in both commands (live runs consume your allowance):

```text
python -B scripts/benchmark_tokens.py --run .codex/reproduce/before --policy benchmarks/token-efficiency/baseline-policy --fixed-team --prepared-handoffs --model gpt-6-sol --effort medium
python -B scripts/benchmark_tokens.py --run .codex/reproduce/after --policy benchmarks/token-efficiency/tested-handoff-policy --fixed-team --prepared-handoffs --model gpt-6-sol --effort medium
python -B scripts/benchmark_tokens.py --compare .codex/reproduce/before .codex/reproduce/after
```

Use `--codex /path/to/codex` for a specific native executable. Available models
and clients may differ from the measured version. See
[measurement details](token-efficiency.md) for protocol and accounting checks.
